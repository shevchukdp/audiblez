🔊 Audiblez

Turn e-books into audiobooks

Audiblez reads .epub books aloud with Kokoro-82M text-to-speech and stitches the result into a single .m4b audiobook — ready for VLC, Apple Books, or any audiobook player.

⚡ What it does

Audiblez generates .m4b audiobooks from regular .epub e-books using Kokoro's high-quality, natural-sounding speech synthesis. On a Google Colab T4 GPU it can convert ~160,000 characters ("Animal's Farm") in about 5 minutes (~600 chars/sec); on an M2 MacBook CPU it takes about an hour (~60 chars/sec).

📖 Chapter aware

Automatically splits the book into chapters and converts each one, then reassembles a single .m4b.

🎙️ 100+ voices

American, British, Spanish, French, Hindi, Italian, Japanese, Brazilian Portuguese and Mandarin Chinese.

🎚️ Speed control

Speed the narration up or down from 0.5× to 2.0×.

🖐️ Pick chapters

Manually choose which sections to read out loud with the --pick option.

🚀 CUDA support

Pass --cuda to run synthesis on a GPU via PyTorch.

🖥️ Native GUI

A purpose-built Rust + egui launcher for Windows replaces the old Python/wxPython UI.

📦 Install

Requires Python 3, plus espeak-ng and ffmpeg on your machine.

# Ubuntu / Debian
sudo apt install ffmpeg espeak-ng
pip install audiblez

# macOS
brew install ffmpeg espeak-ng
pip install audiblez

Then convert a book in one line:

audiblez book.epub -v af_sky

This creates book_chapter_1.wav, book_chapter_2.wav, … and finally a book.m4b with the whole book.

💻 Command line

usage: audiblez [-h] [-v VOICE] [-p] [-s SPEED] [-c] [-o FOLDER] epub_file_path

  -v VOICE, --voice VOICE   Choose narrating voice (e.g. af_sky)
  -p, --pick                Interactively select which chapters to read
  -s SPEED, --speed SPEED   Set speed from 0.5 to 2.0
  -c, --cuda                Use GPU via Cuda in Torch if available
  -o FOLDER, --output FOLDER  Output folder for the audiobook
The first letter of a voice is the language code and the second is the speaker's gender, e.g. im_nicola is an Italian male voice.

🧩 The Python GUI

A simple graphical interface to run audiblez. Install the extra dependencies and run audiblez-ui.

pip install audiblez pillow wxpython
audiblez-ui

On Ubuntu/Debian you also need the GTK dev headers:

sudo apt install libgtk-3-dev

🪟 Native Windows app (new)

gui-rs/ is a native Windows GUI written in Rust + egui, replacing the Python/wxPython audiblez/ui.py. It talks to the audiblez controller the same way — over the same JSON protocol — so it works either against a local controller (127.0.0.1:8765) or a remote one.

Native & fast

egui/eframe, single Windows executable — no Python runtime needed at launch.

Transport-agnostic

Local or remote controller via the existing JSON protocol.

File pickers

Native Windows open-file dialogs to choose the .epub.

# build the native Windows executable
cargo build --release --target x86_64-pc-windows-gnullvm
# -> target/x86_64-pc-windows-gnullvm/release/audiblez.exe

Built with the LLVM-GNU (gnullvm) target and the bundled rust-lld linker (see gui-rs/.cargo/config.toml). The .epub is sent to the controller, which runs the same Python pipeline (TTS → ffmpeg) under the hood.

🌐 Remote TTS server

remote_tts_server/ ships a standalone Kokoro TTS server so the native GUI (or any client) can run on a different machine than the one doing the synthesis.

cd remote_tts_server
pip install -r requirements.txt
python server.py            # listens on 127.0.0.1:8765 by default

Point the GUI's controller URL at the host running the server, and it will stream jobs over the same JSON protocol.
